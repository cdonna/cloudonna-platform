# Sprint 6 — 10. UI Architecture

## Route map

```
/login                                                        — magic link + password
/onboarding                                                   — first-time: create or join an organization
/[orgSlug]                                                    — Organization Switcher lands here
/[orgSlug]/settings/members                                   — member list, invitations, roles
/[orgSlug]/[workspaceSlug]                                    — Workspace Dashboard
/[orgSlug]/[workspaceSlug]/[projectSlug]                      — Project Dashboard
/[orgSlug]/[workspaceSlug]/[projectSlug]/new                  — today's wizard, unchanged, now project-scoped
/[orgSlug]/[workspaceSlug]/[projectSlug]/decisions            — Decision History
/[orgSlug]/[workspaceSlug]/[projectSlug]/decisions/[humanId]  — Decision Detail (current version)
/[orgSlug]/[workspaceSlug]/[projectSlug]/decisions/[humanId]/compare — Version Compare
```

`humanId` (`CDD-2026-000152`) is the routing param — a display convenience graduating to an address, never a security boundary; RLS re-checks tenancy on every load regardless of what's in the URL.

## The nine screens, named in the brief

| Screen | Status | Notes |
|---|---|---|
| **Login** | New | Magic link primary, password fallback. |
| **Organization Switcher** | New | Persistent, top-level — a user in more than one organization switches without a full page reload. |
| **Workspace Dashboard** | New | Project list within a workspace. |
| **Project Dashboard** | New | Entry point to "run a new assessment," plus a summary of the project's decision history. |
| **Decision History** | New | List of saved decisions in a project — current versions only by default, status pills, `human_id`, date. |
| **Decision Detail** | New | Renders a saved `DecisionReport` through the **same `ResultPanel`/`IntelligenceTab` components already in production**, unmodified — a saved decision's `deterministic_output`/`enrichment` are shaped identically to a live one, so there is no new rendering code, only a new data source. Adds: timeline, approval status/actions, comments, outcome-tracking form. |
| **Version Compare** | New | Side-by-side score/ranking deltas between two versions in a lineage. |
| **Timeline** | New | Rendered from `audit_logs` + version-creation events (`06-timeline.md`) — no separate data model. |
| **Outcome Tracking** | New | Form for expected/actual outcomes, success measures, implementation status, retrospective notes. |

## What's reused, unchanged, deliberately not rebuilt

- The six-step wizard (Company → Landscape → Goals → Constraints → Review → Analysis) — only its container changes (now rendered inside a project route).
- `ResultPanel`, `IntelligenceTab`, and every existing result tab — a saved decision and a live one render through identical code.
- Sprint 5's accessibility conventions: `role="status" aria-live="polite"` for async state, real `<label>`s, keyboard-navigable tab controls — inherited, not re-derived.

## The "Save Decision" action

The existing "Save decision" button on `ResultPanel` today is a session-local, in-memory-only toggle with no persistence. **Recommendation: repurpose it, not duplicate it.** If authenticated with a project context, it performs the real save; if unauthenticated, it prompts sign-in first rather than silently no-op'ing. Two visually identical "save" buttons meaning different things on the same screen would be a worse outcome than one button whose behavior depends on session state.

## Honest states, everywhere

No misleading "AI knows everything" language, ever — a direct continuation of Sprint 5's own standard. Every async action (save, approve, replay) shows a real loading state and a real, specific error on failure, never a silent hang. Decision History's status pills reuse the same visual language as `ResultPanel`'s existing fallback-status indicator, rather than inventing a second status-pill design language.

## What this document does not decide

- Exact visual design (spacing, color) — an implementation-phase decision, consistent with how Sprint 5's own UI wasn't specified at the architecture stage.
- Whether workspace navigation is a dropdown, sidebar, or full page — a UI-implementation call, not architectural.
