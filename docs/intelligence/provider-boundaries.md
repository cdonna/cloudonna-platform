# Provider Boundaries

**Files:** `intelligence/provider.ts`, `intelligence/config.ts`, `intelligence/select-provider.ts`,
`intelligence/providers/deterministic-provider.ts`, `intelligence/providers/openai-provider.ts`

## The interface

```ts
interface IntelligenceProvider {
  readonly id: string;
  readonly model: string | null; // null for a provider with no model (the deterministic one)
  enrich(request: IntelligenceRequest): Promise<IntelligenceResult>;
}

type IntelligenceResult =
  | { status: "ok"; enrichment: IntelligenceEnrichment }
  | { status: Exclude<EnrichmentStatus, "ok">; reason: string };
```

Nothing in this interface, or anything it references
(`IntelligenceRequest`, `IntelligenceEnrichment`, `IntelligenceResult`),
imports React, Next.js, an OpenAI SDK type, or Supabase. Verified
structurally, not just by claim: `intelligence/types.ts` and
`intelligence/provider.ts` import only from within this same domain.

There is no "partial success" variant. `IntelligenceResult` makes a
partial result structurally unrepresentable, not just discouraged.

## Two providers ship in Sprint 5.2

| | `deterministicIntelligenceProvider` | `createOpenAIIntelligenceProvider(config)` |
|---|---|---|
| `id` | `"deterministic-v1"` | `` `openai-${model}` `` |
| `model` | `null` | the configured model string |
| Network call | Never | Yes, server-only |
| Always succeeds? | Yes, by construction | No — every failure mode in `fallback-and-failure-model.md` applies |
| File | `providers/deterministic-provider.ts` | `providers/openai-provider.ts` |

### `deterministicIntelligenceProvider`

Transforms an `EvidencePackage` into `IntelligenceEnrichment` using
template functions — string interpolation over already-computed facts, no
network call, no async I/O (the `Promise` in its signature resolves
synchronously). Every field is passed through a shared `cap()`/`capList()`
helper against `ENRICHMENT_BOUNDS` before being returned — this provider
is guaranteed, by construction, to never fail its own enrichment's schema
validation due to a length overflow. This is not a test mock — it's the
real production default for every environment without a configured
external provider.

Its `disclosure` field always reads: *"Generated by deterministic
templates from Donna's own computed results — no AI model was used, and
no score or ranking was affected by this text."*

### `createOpenAIIntelligenceProvider(config)`

The first real external provider. `import "server-only"` at the top of
`openai-provider.ts` (and `config.ts`, and `select-provider.ts`) makes
"never importable from a client component" a **build-time guarantee** —
verified directly: a `grep` of `.next/static` after `npm run build` finds
zero occurrences of `OPENAI_API_KEY` or any OpenAI SDK call in any
client-side chunk.

Uses `client.chat.completions.create()` with `response_format:
zodResponseFormat(intelligenceEnrichmentSchema, ...)` — OpenAI's
structured-output JSON-schema enforcement, built directly from the same
Zod schema `schema.ts` validates every other provider's output against.
Deliberately does **not** use the SDK's own `.parse()` auto-parsing
convenience: this provider parses `message.content` with `JSON.parse()`
and validates it through `intelligenceEnrichmentSchema.safeParse()`
itself — the exact same gate the deterministic provider's output would
have to pass if it were ever checked (it never fails). No provider gets
to skip a step another provider doesn't skip.

Errors are normalized through `classifyOpenAIError()` into a small,
SDK-independent `IntelligenceError` shape before becoming an
`IntelligenceResult` — `RateLimitError` → `rate_limited`,
`APIConnectionTimeoutError` / an aborted request → `timeout`, any other
`APIError` → `unavailable`, anything unrecognized → `unavailable`. The
SDK's own error message is never included in the classified result — see
`classifyOpenAIError`'s tests in `openai-provider.test.ts` for the
specific assertion that a real API key or connection detail never
survives classification.

## `selectIntelligenceProvider(config)`

The one function that constructs a provider from configuration —
`intelligence/select-provider.ts`, also `server-only`. Returns the OpenAI
provider only when `config.provider === "openai" && config.apiKey` is
truthy; the deterministic provider in every other case, including a
misconfigured `provider: "openai"` with no key (defensive — should be
unreachable given how `config.ts` derives `provider`, but never trusted
blindly).

## `loadIntelligenceConfig()`

`intelligence/config.ts` is the **only** file in this entire domain that
reads `process.env` — verified by grep, not assumed. Reads
`OPENAI_API_KEY`, `DONNA_AI_MODEL` (default `gpt-4o-mini`, never hardcoded
anywhere else), `DONNA_AI_TIMEOUT_MS`, `DONNA_AI_MAX_OUTPUT_TOKENS`,
`DONNA_AI_MAX_RETRIES` — malformed numeric env values fall back to safe
defaults rather than producing `NaN`. See `.env.example`.

## Testing without a live provider

All 92 default-run tests in `intelligence/__tests__/` exercise either the
real deterministic provider or a mocked OpenAI client
(`openai-provider-mocked.test.ts`, using `vi.mock("openai", ...)` to
replace the SDK's `chat.completions.create` with a fake that returns
realistic response shapes — valid JSON, malformed JSON, a refusal, a
thrown network error) — zero network access, zero API keys, zero
environment variables required for any of them.

`openai-provider.live.test.ts` is the only file that makes a real network
call. It's excluded from the default run by `vitest.config.mts`'s
`**/*.live.test.ts` pattern **and** individually gated with
`describe.skipIf(!hasRealKey)` — belt and suspenders, so it can never run
by accident even if the config exclusion were ever changed.
